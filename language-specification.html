Compiler Language Specification

Used in Programming Exercises 0 - 4

Overview

Your completed compiler must implement a strongly-typed language where your constants and procedure declarations are done upfront.  This document outlines the minimal functional requirements your language must satisfy in order to receive full credit on the Programming Exercises.  

NOTE:  While you are free to implement functionality above and beyond what is specified in this document, you may find that doing so is more trouble than it is worth--especially as you get to PEX 3 and 4.  This might be the only time in your academic career when your instructor is going to say "It's okay.  Do the minimum."

 

 

1.  Variables

  • 1.1  Identifiers must be legal C variables
    • Ex:  Variable names must allow “_”, but not two in a row
    • Ex:  Variable names can start with a letter or underscore, but cannot start with a number
  • 1.2  Your language must allow for string, integer and floating-point constant AND variable declarations
    • No Booleans, enumerated types, etc. are required
    • Variables do not need to be initialized when declared
    • Constants must be initialized when declared
  • 1.3  Variable assignments must be allowed
  • 1.4  Constant declarations should appear before your functions.  Constants do not need to be declared in a function or in your main.
  • 1.5  String literals
    • Strings must allow the user to include quotation marks using an escape character
    • Strings must also allow you to store the escape character
  • 1.6  Integer and floating-point literals
    • (PEX 1 Hint) Your lexer should treat "-3" as 2 separate tokens (“-“ and “3”)
    • Exponential notation for floating point literals are required (e.g., 5.2e-4)

 

2.  Program Control

  • 2.1  Your language must support IF/ELSE statements (no Else If is required)
  • 2.2  Your language must support WHILE loops (no FOR loops, DO/WHILEs, or BREAKS are required)
  • 2.3  Methods or Procedures must be defined after constants, but before your MAIN
    • No return values required
    • Must support 0..n parameters
  • 2.4  Main method is not required to have arguments and may be required to have a particular name
    • The main method should always be LAST in your program

 

3.  Operations

  • 3.1  Your language must support the following operations 
    • addition 
    • subtraction 
    • negation (e.g., -5)
    • multiplication 
    • division
    • parenthesis
    • AND
    • OR
    • NOT
    • equivalence
    • greater than / greater than or equal to
    • less than / less than or equal to
  • 3.2  Operators must use the standard order of operations:
    Operations (1= Highest Precedence)
    1 Parenthesis
    2 Unary operators
    3 Multiplication, division
    4 Addition, subtraction
    5 Comparisons: <.<=,>,>=
    6 Comparisons: equal and not equal
    7 Logical NOT
    8

    Logical AND
    9

    Logical OR
  • (PEX 2 Hint)  Your parser should not attempt to consider boolean expressions different from mathematical ones
  • (PEX 3 Hint)  Your semantic analyzer should not allow operators (+, -, *, ==, >=, <=, <, <) to be used on strings
  • 3.3  (PEX 3) Do not allow chaining for boolean operations (e.g., 3 < x < 5)
  • 3.4  (PEX2) Allow chaining for math operations (e.g., 3 + x - 5)

 

Comments

  • Your language must support single line comments (no /* . . . */ style comments required)
